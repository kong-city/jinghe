## 1. 能力定义（用户 2026-11-15 确认的 S5 范围）

用户给单个视频链接或播放列表链接，软件在本机下载媒体、按已有 S4 视频 handler 提取为 `.md`（元数据 / 音轨转写 / 画面·字幕三区块），产物只落 `out/derived/`，绝不写冻结对账盘。

- 输入：`http` / `https` 链接（单条或播放列表）
- 下载：本机 `yt-dlp`（已装齐，软件不下载/不打包/不自动安装）
- 解析：下载得到的媒体走**既有 `video_transcribe.py` 独立 handler**（S4 硬裁决：绝不复用音频路径）
- 批量：播放列表逐条入队、逐条成功/失败/跳过，单条失败不拖垮整批
- 编排：`/api/media/run` / `status` / `cancel`（契约里专为 S5 预留的批量端点）

## 3. 安全契约（S5 重点，全部为硬红线）

| 风险 | 强制措施 |
|---|---|
| SSRF / 内网探测 | 只接受 `http`/`https`；解析后**逐跳校验 IP**，拒绝环回/私网/链路本地/保留段；DNS 重绑定须固定首次解析结果并用于连接；重定向逐跳重校验，最大跳数上限 |
| 超大/超长资源 | 大小上限、时长上限、分片数上限；流式写入、超限即断链并清理 |
| 下载完整性 | `.part` 临时文件 + 原子替换；取消即清理（参照 `_download_release_asset()` 白名单范式） |
| 任意路径/程序启动 | 沿用 `/api/open` 白名单收敛；新端点不接受任意绝对路径 |
| 平台与合规 | **不内置任何平台凭据，不提供绕过登录/付费/DRM/防盗链的能力**；仅处理用户有权访问的内容；产物归属与版权由用户负责 |
| 隐私 | 链接与日志不回传；错误文案不泄漏敏感信息 |

## 4. 端点候选形状（增量端点，不改既有路由）

- `POST /api/link/inspect` —— 链接预检（只读：URL 形状、DNS/IP 校验结果、是否播放列表、yt-dlp 健康度），零下载
- `POST /api/media/run` —— 提交链接（单条/播放列表），后台 Job 下载 + 调 S4 解析，立即返回
- `GET  /api/media/status?since=N` —— 批量进度增量事件（独立队列，不污染阶段 1 / 音频 / 视频三条）
- `POST /api/media/cancel` —— 取消批量任务，终止 yt-dlp 子进程树并清理 `.part`
- `GET  /api/tools/probe` 顶层增量字段 `link_resolve` —— 真实能力状态（yt-dlp 可用/不可用 + 原因）

## 7. 开工闸门：请用户确认「可接受范围」（R2）

契约明写「S5 开工前再确认可接受范围」。以下四项请用户拍板，确认后我再写功能代码：

**① URL 白名单口径**（三选一）
- A. **通用公网**：任何公网 `http`/`https` 链接，只做 SSRF 防护（禁内网/保留段），不按域名过滤
- B. **知名视频平台白名单**：仅预置的若干平台域名（如 B站/YouTube 等），其余拒绝

**② 播放列表 / 批量规模**
