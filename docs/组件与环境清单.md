# 精核 · 组件与环境清单

> **用途**：让两台终端的精核运行环境尽量一致。本文件是**声明式清单**，不是环境快照。
> 另一台终端的精核会读取本文件顶部的机器可读块，比对本机实际状态，报告「缺哪些 / 版本差多少」，
> **默认绝不自动下载或安装**——补缺省走设置页现有的「启用」按钮（用户手动点击令牌）。
> v1.6.3 起增加「后台静默补齐」开关，但**默认关闭**；仅测试/显式授权场景才会开启，客户安装后行为不变。
>
> 生成基线：**精核 v1.6.0** · 采集日期 **2026-11-24** · 采集机 Windows x64
> 真源：`knowledge/components.py::COMPONENTS` + 采集机 `%LOCALAPPDATA%\Jinghe\components\venv` 实测

## 一、这台机器的实测状态（采集基线）

| 组件 | 类型 | 安装方式 | 本机版本 | 来源 | 用途 |
|---|---|---|---|---|---|
| FFmpeg | zip | 下载解压到组件目录 | 未安装（系统 PATH 也无） | 阿里云 PyPI 镜像（imageio-ffmpeg wheel，内置 9.0.2） | 音视频抽轨、字幕导出、链接后处理 |
| Whisper | pip | venv 内 `openai-whisper` | **20250625** | 阿里云 PyPI 镜像 | 音频转写 |
| yt-dlp | pip | venv 内 `yt-dlp` | **2026.10.26** | 阿里云 PyPI 镜像 | 链接下载解析、订阅抓取 |
| 扫描件 OCR | pylib | venv 内 `pymupdf + rapidocr-onnxruntime` | 未安装 | 阿里云 PyPI 镜像 | 扫描件 PDF 文字识别 |
| VC++ 运行库 | system | 用户下载微软官方安装包自行安装（需管理员权限） | **缺失**（缺 `vcruntime140_threads.dll` / `msvcp140_atomic_wait.dll`） | 微软 aka.ms 官方直链 | Whisper / torch 原生依赖 |

**运行时基线**：Python 3.13.14（系统 = venv 一致）· venv 隔离（`include-system-site-packages=false`）· torch 2.15.0 · numpy 2.5.5。

## 二、另一台终端怎么对齐

1. **放清单**：把本文件放到新终端的 `jinghe-desktop/docs/组件与环境清单.md`（跟代码一起走，git pull 即可）。
2. **软件自动比对**：启动精核 → 设置页「相关组件」卡片会读取本文件顶部 JSON 块，与本机实际探测结果比对，显示对齐状态：
   - `一致`：本机已装且版本与期望相同；
   - `版本不同`：本机已装但版本与清单期望不一致（仅提示，不强制降级/升级）；
   - `缺失`：本机未装，走「启用」按钮补；
   - `无需版本对齐`：清单未记录期望版本（如 FFmpeg / OCR），以探测可用为准。
3. **手动补缺**：点组件行的「启用」按钮 —— 走软件现有的安装流程（受手动令牌保护）。
   如需在测试环境批量补齐，可在设置里显式开启「后台静默补齐」（默认关闭，客户安装后行为不变）。
4. **Python 运行时**：有系统 Python 3.13.x 时直接用；无 Python 时精核会引导启用便携运行时（`RUNTIME_DIR`），仍须用户点令牌。

## 三、红线与边界

- **只读声明**：本清单只描述"期望是什么"，软件读取后**不会**自动下载、安装、升级、降级任何组件。
- **版本不强对齐**：`reference_version` 是采集机的实测值，供参考；另一终端版本不同不算错误，只要组件可用即可。
- **探测口径统一**：可用性判定仍走 `knowledge/components.py` 的现有探测（`_probe_one` / `_probe_pylib`），含 DLL 预检与真实 import 校验，清单不另起一套判据。
- **原生依赖**：Whisper 需要 Microsoft Visual C++ 运行库；缺 `vcruntime140*.dll` / `msvcp140*.dll` 会导致"装了但用不了"，探测会如实报 `error` 状态并给出指引。
- **系统依赖只引导不安装**（v1.8.0）：`kind=system` 的 VC++ 运行库项只做探测 + 打开官方下载页，**绝不进 install 令牌链路、不静默下载、不弹 UAC**；装完需重启软件。清单比对中 system 项同样只读。

## 四、怎么更新这份清单

当采集机组件版本变化后，重新采集本机实测值并更新顶部 JSON 块的 `reference_version` / `runtime_baseline` 与第二节表格；`generated_at` 同步刷新。声明部分（`kind` / `source` / `package` / `probe` / `exe` / `probe_module`）必须与 `knowledge/components.py::COMPONENTS` 保持一致，新增组件时两边同步。

> 机器可读块用 `<!-- JINGHE_COMPONENT_MANIFEST_BEGIN ... END -->` 包裹，纯文本正则即可提取，零第三方依赖；解析器见 `knowledge/components.py::load_manifest()`。

## 五、环境韧性与自动重试（v1.8.2）

换电脑/换环境时，下载会受到网络、系统依赖、Python 环境与安全软件影响。v1.8.2 起：

- **安装前预检**：点「启用」先检查目录可写、Python 解释器、venv 健康与 VC++ 运行库；阻断项直接给出人话提示和官方安装入口，不再装到一半才失败。VC++ 缺项只拦 Whisper（torch 硬依赖），不连坐 FFmpeg / yt-dlp / OCR。
- **坏 venv 自愈**：检测到 pip 残缺（`No module named pip._internal` 等）时，自动换一个全新 `venv2`/`venv3` 槽位重建，**旧目录一律保留**——避开安全软件对删除操作的拦截。
- **自动重试**：下载网络类失败最多重试 2 次、pip 失败最多重试 1 次，进度里可见「重试 x/y」；用户取消与 SHA256 校验不符**绝不重试**。
- **装完即刷新**：安装完成后清工具探测缓存并刷新 PATH，不再要求重启软件才看到新组件。
- **环境诊断**：设置页「相关组件」卡片新增「环境诊断」按钮，走 `GET /api/components/environment` 输出 Python / venv / VC++ / 目录权限 / PATH / 重试配置，纯本地只读、零网络，便于换机排查与问题反馈。
