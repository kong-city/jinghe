## 0. 一句话目标

把精核已产出的结构化产物（`out/md/*.md`、`MERGED.md`、`INDEX.md`、`provenance.json`）**沉淀为可检索、可增量维护的本机知识库**，并提供把「提取 → 提纯 → 入库」串起来的本地自动化能力——全程离线、零第三方运行时依赖、不碰冻结内核。

---

## 1. 为什么要做（问题陈述）

现状：精核把文件提取提纯成带来源锚点的 Markdown，但产物是**一次性、按批次散落**在 `out-<时间戳>/` 目录里。用户已有的痛点：
- 跨批次检索困难：想找"上次那份 PDF 里关于 X 的结论"，只能翻目录。
- 重复提取：同一份文件多次丢进来，没有去重，浪费额度与时间。
- 无沉淀：产物用完即弃，没有累积成可查询的知识资产。

阶段 4 把这些缺口补上，但仍守住项目的核心信条：**可回溯、不造假、离线、零依赖**。

## 3. 能力定义（候选范围，待用户在第 7 节拍板）

### 3.1 入库（ingest）
- 输入：一个或多个既有产物目录（`out-<时间戳>/`）或其中的 `.md`。
- 解析：复用产物的 `src` 注释 / doc_id / 块锚点，切分为「条目」（按块或按段落，口径待定）。
- 去重：以 `doc_id + 块锚点 + 内容哈希` 判定重复，重复条目只更新引用计数，不重复存。
- 产物：写入独立知识库目录，默认 `%LOCALAPPDATA%\Jinghe\kb\`（Windows）/ 对应数据目录（macOS），与软件其它数据并列。

### 3.2 检索（query）
- 关键词检索：`sqlite3` FTS5 全文索引（Python 标准库自带，零依赖）+ 项目已有的 TF-ICF / 二元组分词能力复用。
- 结果：返回条目摘要 + 来源标注（文件名 / doc_id / 块锚点），可"打开原文"回跳到产物里的对应位置。
- 语义检索：**默认不做**；若做，作为可插拔增强（本机 ollama embedding），不配置时诚实禁用。

### 3.3 自动化（automation，范围最小）
- 一键流水线：把「提取 → 提纯 → 入库」串成一次点击，产物自动进库。
- 定时 / 监听目录：**默认不做**（避免引入后台常驻复杂度与安全面），列为远期候选。

## 4. 端点候选形状（增量端点，不改既有路由）

仅在 `app.py` 增加新路由，既有 `/api/*` 一字不动：

| 端点 | 方法 | 用途 |
|---|---|---|
| `/api/kb/status` | GET | 知识库是否初始化、条目数、上次入库时间 |
| `/api/kb/ingest` | POST | 把指定产物目录入库（批量、逐条成功/失败） |
| `/api/kb/query` | POST | 关键词检索，返回带来源标注的条目列表 |
| `/api/kb/open-source` | POST | 按 doc_id + 块锚点打开原文产物（复用既有安全打开逻辑） |

- 所有端点走既有鉴权 / 来源围栏约定；带 `Origin` 头的请求一律 403（本机端口不给浏览器用）。
- 未知端点仍返回统一 `404 + {ok:false,error}`。

## 5. 安全契约（硬红线）

1. **路径围栏**：入库与"打开原文"只接受知识库数据目录与产物目录下的路径，拒绝任意路径（防目录穿越 / 任意文件读取）。
2. **不联网**：阶段 4 本体零网络请求；语义检索若启用，仅访问用户显式配置的本机 ollama 地址。
3. **不造假**：检索结果不得拼接产物中不存在的句子；摘要若由模型生成，须按 AI 补写隔离规则标记。
4. **数据所有权**：知识库数据属于用户，软件退出不清空；卸载时也**不自动删除**知识库目录（与"只摘自己导入的条目"纪律一致）。
5. **AI 补写隔离**：带 `[AI ++ … ++]` 标记的补写内容默认不入库；要入库须用户显式开启且单独标记。
