# 本地打包指南（Windows）

> 记录日期：2026-11-22（首次在本地完整走通）
> 适用：想在本机产出安装包/免安装包，而不只依赖 GitHub CI 产物

---

## 一、两条命令，产出两类包

```bash
# ① 后端单文件 exe（PyInstaller）→ dist/Jinghe-<版本>.exe（约 10MB）
python build.py

# ② Electron 安装包 → electron/release/Jinghe-<版本>-setup.exe（约 85MB）
cd electron && npm run dist -- --publish never
```

**两者缺一不可**：安装包的 `extraResources` 从 `electron/backend/` 拷贝后端 exe，
而 `electron/backend/` 里的 exe 是被 gitignore 的空目录，**必须先手动放进去**：

```bash
cp -f dist/Jinghe-<版本>.exe electron/backend/Jinghe.exe
```

> CI 里这一步是自动的（`.github/workflows/ci.yml` 第 91–95 行：建目录 → 复制）。
> 本地漏了这一步，**安装包能打出来但装完启动不了**（找不到后端）。

## 二、本地打包的三个坑（都真实踩过）

### 坑 1：`ELECTRON_RUN_AS_NODE` 让 Electron 变纯 Node 模式

某些开发环境/沙箱会注入 `ELECTRON_RUN_AS_NODE=1`。此时运行打包好的应用：

- `Jinghe.exe --version` 输出的是 **Node 版本**（如 `v20.18.0`）而不是 Electron 版本；
- **main.js 一行都不执行** —— 没有窗口、没有后端、进程却活着；
- 表现为「双击没反应」，且**没有任何错误信息**（GUI 程序无控制台）。

排查方法：
```bash
echo "[${ELECTRON_RUN_AS_NODE:-未设置}]"
```
启动前必须清除：
```bash
env -u ELECTRON_RUN_AS_NODE -u NODE_OPTIONS ./Jinghe.exe
```
> 判据：`--version` 若返回 Node 版本（v20.x）而不是 Electron 版本，说明处于 Node 模式。

### 坑 2：`nsis-resources` 在 npmmirror 镜像缺失

electron-builder 需要 NSIS 及其资源包。npmmirror 有 `nsis-3.0.4.1` 但
`nsis-resources-3.4.1` 返回 **Bad Gateway**。

解法：官方源下载该包（SHA-512 必须匹配，否则 electron-builder 拒绝使用）：
```bash
curl -L -o nsis-resources-3.4.1.7z \
  "https://github.com/electron-userland/electron-builder-binaries/releases/download/nsis-resources-3.4.1/nsis-resources-3.4.1.7z"
```
校验值（base64 SHA-512）：
`Dqd6g+2buwwvoG1Vyf6BHR1b+25QMmPcwZx40atOT57gH27rkjOei1L0JTldxZu4NFoEmW4kJgZ3DlSWVON3+Q==`

装进缓存（需 `7za` 在 PATH；仓库自带 `electron/node_modules/7zip-bin/win/x64/7za.exe`）：
```bash
export PATH="$PWD/node_modules/7zip-bin/win/x64:$PATH"
./node_modules/app-builder-bin/win/x64/app-builder.exe download-artifact \
  --name=nsis-resources --url="http://127.0.0.1:<本地静态服务端口>/nsis-resources-3.4.1.7z" \
  --sha512="Dqd6g+2buwwvoG1Vyf6BHR1b+25QMmPcwZx40atOT57gH27rkjOei1L0JTldxZu4NFoEmW4kJgZ3DlSWVON3+Q=="
```
> `file://` 协议不被支持，必须走 http（可起 `python -m http.server` 本地供源）。

### 坑 3：打包前必须结束占用 win-unpacked 的进程

electron-builder 要重写 `release/win-unpacked/`，若应用还在运行会报
`ffmpeg.dll: Access is denied` 而失败。先结束残留进程再打包。

## 三、验证打包产物

```bash
# 后端 exe 可运行
./dist/Jinghe-1.2.4.exe --cli --version          # 应输出 1.2.4

# 安装包内确实含后端
ls electron/release/win-unpacked/resources/backend/Jinghe.exe

# 发版门禁（含 exe 校验）
python tools/check_release.py --require-exe

# 打包态整机验证（记得清 ELECTRON_RUN_AS_NODE）
env -u ELECTRON_RUN_AS_NODE -u NODE_OPTIONS ./electron/release/win-unpacked/Jinghe.exe
```
启动后应看到：
- `%LOCALAPPDATA%\Jinghe\shell.log` 记录 `main.js 已加载 → 外壳就绪 → 启动后端 → 托盘已创建`；
- `http://127.0.0.1:54321/` 可访问，`/api/state` 返回版本号。

## 四、产物位置

| 产物 | 路径 |
|---|---|
| 后端单文件 exe | `dist/Jinghe-<版本>.exe` |
| 安装包 | `electron/release/Jinghe-<版本>-setup.exe` |
| 自动更新元数据 | `electron/release/latest.yml` |
| 免安装目录 | `electron/release/win-unpacked/` |
| 外壳诊断日志 | `%LOCALAPPDATA%\Jinghe\shell.log` |
| 后端日志 | `%LOCALAPPDATA%\Jinghe\app.log` |

以上产物均在 `.gitignore` 内，不会误提交。
