# S14 · UI 信息架构重组（说明）

> 日期：2026-11-22
> 基线：v1.2.3
> 触发：用户对界面布局不满——「同类型功能拆得乱七八糟，找对应功能难」

---

## 一、问题诊断

把 `ui/index.html` 的 7 个导航页与全部卡片拆开看，问题有三：

1. **一条流水线被拆成三个平级页**：加工（转 md）→ 精读（提纯核心）→ 修订（改写补充）本应层层递进，却做成三个并列导航，产物靠手动选择/下拉传递，用户在页间反复跳。
2. **同类「内容来源」分散**：视频链接提取在"加工"页，订阅博主在"知识库"页——都是"把外部内容拿进来"，用户不会去知识库找订阅。
3. **配置与术语割裂**：提纯模式/迭代轮数在"设置→精读后端"，产物操作在加工页；"加工/精读/修订/提纯"多个词描述相邻概念。

## 二、改造策略：重做引导层，保留兼容骨架

**红线**：测试对 UI 有 109 条字符串断言，锁死 7 个 `data-page`、7 个 `page-X` 容器、页面物理顺序（home<process<kb<refine<revise<settings<about）及各锚点按钮归属段落。因此**不删页面、不改顺序、不挪锚点按钮、不新增/删除 API**。

在这个前提下做四件事：

| 改造 | 内容 | 效果 |
|---|---|---|
| 导航归组 | 7 个平级入口用 4 个分组标题包起来：获取内容（首页/加工）、加工流水线（精读/修订）、知识沉淀（知识库）、系统（设置/关于） | 侧栏一眼看出功能归属；折叠态自动隐藏分组标题 |
| 全局任务步骤条 | 页头下方加 4 步条「①获取内容→②提纯核心→③改写补充→④沉淀检索」，任意页可见、点哪跳哪、当前步高亮 | 流水线可视化，用户知道自己在哪一步、下一步去哪 |
| 加工页流程指引 | 加工页顶部加指引卡：去提纯 / 去改写 / 订阅博主·知识库，按钮直接跳转 | 订阅功能从"藏在知识库"变得可发现 |
| 术语统一 | PAGE_META 标题改为带阶段编号的表述（如「② 加工 · 提纯核心」「④ 沉淀 · 知识库」），副标题说清每步做什么 | 建立"获取→加工→沉淀"的统一心智模型 |

## 三、验收

- **全量测试 237/237 OK**（新增 `test_ui_layout.py` 8 项，旧 109 条 UI 断言一条未破）；
- **发版门禁 16/16**；
- **真实浏览器 CDP 实测全部通过**：4 个导航分组与标题、步骤条 4 步且首页高亮、点"提纯"步跳到精读页并同步高亮、加工页指引跳知识库、折叠态分组标题隐藏。
- 未改任何后端逻辑、功能 id、API 端点。

- 提纯设置从设置页移入加工页上下文（本次仅在副标题中说明位置）。
