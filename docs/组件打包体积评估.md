# 精核 · 组件打包体积评估

> 目的：回答「组件多大 / 打进安装包会膨胀到多少」，为「是否把组件随包分发」提供决策依据。
> 采集日期 2026-11-24 · 采集机 Windows x64 · 数据来源见文末「口径说明」。

## 一、结论先行

- **四个组件裸文件合计约 1.19 GB**，其中 Whisper 依赖链一家独占 810 MB（68%），核心是 torch 514 MB。
- **全部打进安装包**：NSIS/LZMA 压缩后安装包预计 **600–850 MB**（当前 85 MB，膨胀 7–10 倍），安装后磁盘占用 **1.3–1.6 GB**。
- **打进包能解决的是「下载失败」**，解决不了「装了用不了」——后者根因是 VC++ 运行库缺失与 Python 版本漂移，属于运行环境问题，不是体积问题。
- **推荐路线 B**：只把 FFmpeg + yt-dlp + OCR 三个轻量组件（约 410 MB 裸）随包分发，安装包约 200–300 MB；Whisper 维持按需安装。理由见第四节。

| 组件 | 安装后裸体积 | 状态 | 数据性质 | 说明 |
|---|---:|---|---|---|

| ├ torch | 514 MB | 已装 | 实测 | 最大单块，含 lib 目录，二进制压缩率极低 |
| ├ llvmlite | 116 MB | 已装 | 实测 | numba JIT 后端 |
| ├ sympy | 65 MB | 已装 | 实测 | torch 传递依赖 |
| ├ numpy + numpy.libs | 51 MB | 已装 | 实测 | |
| ├ numba | 26 MB | 已装 | 实测 | |
| └ 其余（networkx/tiktoken/whisper 本体等） | 38 MB | 已装 | 实测 | |
| **yt-dlp** | **20 MB** | 本机已装 | **实测** | 纯 Python 包，无原生依赖 |
| **扫描件 OCR** | **~200–250 MB** | 本机未装 | 估算 | pymupdf + rapidocr-onnxruntime + opencv-python，依 wheel 元数据推算解压后体积 |
| **FFmpeg** | **~165 MB** | 本机未装 | 估算 | gyan essentials zip 解压后只取 ffmpeg.exe + ffprobe.exe 两个静态二进制 |
| **Whisper base 模型** | **~140 MB** | 未下载 | 公开规格 | 首次运行下载到 `components/models`（当前目录不存在），默认模型 `base` |

**裸文件合计**：810 + 20 + 225 + 165 = **约 1.19 GB**（不含模型与便携运行时）。

## 三、打进安装包后的空间账

当前 `Jinghe-1.6.3-setup.exe` = **85 MB**，内容为 Electron 运行时（约 60 MB）+ 后端 exe（9.7 MB）+ UI/图标。**组件一个都没进包**（`build.spec` 里 `binaries=[]`，`electron/package.json` 的 `extraResources` 只有 `backend/`）。

| 方案 | 随包组件 | 裸文件 | 安装包预估（LZMA 后） | 安装后磁盘占用 |
|---|---|---:|---:|---:|
| 现状 | 无 | 0 | **85 MB** | ~200 MB |
| **B（推荐）** | FFmpeg + yt-dlp + OCR | ~410 MB | **200–300 MB** | ~600 MB |
| A1 | 全部四个（不含模型） | ~1.19 GB | **600–800 MB** | ~1.4 GB |
| A2 | 全部四个 + base 模型 | ~1.33 GB | **700–850 MB** | ~1.55 GB |

**压缩率为何这么低**：torch 的大头是 `.dll` 静态二进制（已被编译器压缩过），LZMA 只能再压 10–30%；`.py` 文件压缩率高但占比小。`base.pt` 模型权重几乎压不动。所以「1.19 GB 裸文件」不等于「1.19 GB 安装包」，但也绝压不到 300 MB 以下。

> 上表安装包体积为**工程估算**，非实测。若确定采用某方案，打一次真包即可得到精确值。

## 四、为什么「组件安装老出问题」——根因不是体积

打进包能消除的，只是三类问题中的第一类：

1. **下载/网络层（打进包可解决）**
   - FFmpeg 走 gyan.dev，国内直连频繁超时（本次评估 HEAD 请求即返回 502）。
   - pip 走阿里云镜像，偶发 `from versions: none`。
   - 这类失败确实是「随包分发」能根治的。

2. **原生依赖层（打进包大部分解决不了）**
   - Whisper 依赖 torch，torch 的 `torch_cpu.dll` 依赖 `VCRUNTIME140_THREADS.dll`；系统缺 VC++ 运行库时报 `WinError 126`——**文件在、pip 装成功、界面显示已安装，真跑就炸**。这是用户实测踩过的最痛的坑。
   - 除非把 VC++ Redistributable 也一并部署（涉及提权或 per-user 部署），光把组件塞进包里没用。

3. **Python 版本层（全量打包才能解决）**
   - venv 用系统 Python 创建，组件 wheel 版本窗口随 Python 版本右移（yt-dlp 要 `>=3.11`，torch 覆盖 cp310–cp315），版本错位导致「装了探不到」。
   - 只有把 Python 解释器 + 预置 venv 一起打进去（即 A 方案的全量形态）才能绕开本机 Python，代价就是 1.2 GB+ 和后续组件升级必须重发大包。

**一句话**：体积是表象，**环境不一致**才是病根。

## 五、方案对比与推荐

| 方案 | 优点 | 代价 / 风险 | 适用场景 |
|---|---|---|---|
| **B：三个轻量组件随包**（推荐） | 安装包仅 200–300 MB；消除最常见的 FFmpeg 下载失败、yt-dlp 镜像失败、OCR 依赖问题；Whisper 保持灵活 | Whisper 仍需用户手动装一次；OCR 约 225 MB 有一定膨胀 | 兼顾体积与稳定性，性价比最高 |
| A：全部随包 | 用户零安装，开箱即用 | 安装包 600–850 MB；VC++ 仍缺；组件升级要重发整包；CI 上传/CDN 流量压力大 | 对「完全离线、零配置」有硬性要求 |
| C：随包带离线 wheel，安装时本地解包 | 不联网也能装；组件可独立更新 | 仍要处理 venv 与 VC++；包体积同 B/A | 内网/无外网部署 |
| D：换掉 torch 依赖（faster-whisper / CTranslate2） | 从根上把 810 MB 降到 ~150 MB + 模型，且不依赖 torch/VC++ | 涉及转写内核改造，需重跑 S3 验收与测试集 | 中长期根治方案，风险与收益都最大 |
| 保持现状 | 零改动 | 下载失败投诉持续 | 不推荐 |

**推荐节奏**：先做 B（低风险、见效快）；若仍频繁收到 Whisper 相关投诉，再评估 D 作为中期方案。

## 六、风险提示与常见坑

- **NSIS 单安装包体积**：600 MB+ 的安装包在部分网络/享体验证环节容易失败，且 GitHub Release 上传、CDN 分发都会明显变慢。
- **组件版本固化**：一旦随包，组件版本就绑死在安装包版本上，之后升级组件必须发新版本，失去当前「清单声明 + 用户按需装」的灵活性。
- **VC++ 运行库**：这是 Whisper 的头号杀手，任何方案都要单独处理（检测 + 明示指引，或随包部署 redistributable）。
- **模型文件**：base 模型 140 MB 是首次运行时下载的，即使组件进包也仍在；若真要完全离线，需把它一并纳入（A2）。
- **压缩收益别高估**：torch 的 dll 压不动，别按「1.2 GB 能压到 400 MB」做规划。

## 七、口径说明

- **实测**：`%LOCALAPPDATA%\Jinghe\components\venv\Lib\site-packages` 逐目录递归求和（Python `os.walk`），组件目录总计 918 MB（含 venv 自身约 68 MB）。
- **估算（OCR）**：依阿里云 PyPI 元数据中 wheel 体积（onnxruntime 15.9 MB、opencv-python 45.7 MB、pymupdf 60.1 MB）按解压膨胀系数推算。
- **估算（FFmpeg）**：gyan.dev essentials zip 解压后仅提取 `ffmpeg.exe` + `ffprobe.exe` 两个静态二进制的常规体积；本次 HEAD 请求经代理返回 502，未取到官方 Content-Length。
- **模型**：`media/audio_transcribe.py` 与 `media/video_transcribe.py` 中 `DEFAULT_MODEL = "base"`，模型由 whisper 自行准备，软件不下载。
