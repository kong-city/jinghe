## 二、安装实测证据（v1.1.5）

- 安装退出码：`0`
- 安装目录文件：`locales/`、`resources/`、`Jinghe.exe`、Chromium DLL、`LICENSE*`、`Uninstall Jinghe.exe` 等
- `resources/backend/Jinghe.exe` 存在（随包后端，目标机无需 Python）
- HKCU 卸载键：`Software\Microsoft\Windows\CurrentVersion\Uninstall\2d2e38da-9402-5028-bf32-1bcb3adca6f6`，DisplayName `Jinghe 1.1.5`
- 快捷方式：桌面 `Jinghe.lnk`、开始菜单 `Programs\Jinghe.lnk`
- 启动后 `GET /api/state` → `version=1.1.5`

## 三、卸载实测证据（v1.1.5）

- 卸载命令：`Uninstall Jinghe.exe /S /currentuser`，退出码 `0`
- 已清理：HKCU 卸载键（0 条残留）、桌面快捷方式（0）、开始菜单快捷方式（0）
- **残留**：`resources/app.asar`（14,725 字节，Archive 属性，无进程占用）
- 修复：`electron/installer.nsh` 增加 `customUnInstall` 宏，显式 `Delete "$INSTDIR\resources\app.asar"` + `RMDir "$INSTDIR\resources"`；`package.json` 的 `nsis.include` 指向该脚本。
- **复测结果（2026-11-21，v1.1.8）**：
  - 安装目录位于 WorkBuddy 工作区内时，静默卸载后 app.asar 仍残留；诊断发现该文件独占打开失败（`EXCLUSIVE_OPEN=FAIL`），是被 WorkBuddy 安全扫描器持有句柄的**测试环境伪影**，非安装包缺陷。
  - 换到工作区外干净路径（`%LOCALAPPDATA%\Temp\jinghe-unins-v118`）从未启动直接静默卸载：卸载退出码 `0`，安装目录已不存在，`app.asar` 不存在，**零残留**。修复确认生效。

## 四、后台进程实测与修复

首次实测（v1.1.5）：

- 启动后进程：`Jinghe.exe` × 4（Electron 主/渲染/GPU/工具进程）+ `resources\backend\Jinghe.exe` × 2（PyInstaller bootloader 父 + Python 子）
- 关窗后：外壳进程立即退出，**后端进程仍占端口 54324 约 20–30 秒**
- 根因：Electron 先 `backend.kill()` 杀掉 bootloader 父进程，2 秒后才 `taskkill /T`；此时父进程已死，真正的 Python 子进程已脱离进程树

修复（v1.1.6 / v1.1.7）：

1. Windows 下**先**对活着的 bootloader 执行 `taskkill /T /F`，再等待退出事件；
2. 退出后增加 `killStrayBackendProcesses()`：按 `ExecutablePath` 完整路径精确匹配 `resources/backend/Jinghe.exe`，只清 backend 目录，绝不误杀外壳；
3. 端口上已有精核后端时记录 PID（`adoptedBackendPid`），关窗一并回收，防止上次崩溃遗留的后端长期占端口；
4. 补 `backend.on('error')`，spawn 失败不再变成未捕获异常；
5. `before-quit` 改为 `preventDefault()` + 异步清理完成后再真正退出；
6. Python 后端增加 `atexit` 子进程树清理与 SIGTERM/SIGINT 处理器；看门狗强制退出前也先清子进程；
7. 新增 8 项静态守护测试（Electron 进程回收 + NSIS 卸载清理）。

## 五、用户数据：卸载询问 + 导出备份（v1.1.9）

用户裁决「提示用户是否删除数据，再增加数据导出」，两项均已实现：

**卸载时询问是否删除数据**（`electron/installer.nsh`）：
- 交互式卸载：`MessageBox MB_YESNO|MB_DEFBUTTON2` 询问，默认按钮「否」（安全）；选「是」才删除 `%LOCALAPPDATA%\Jinghe`（设置 + 知识库 + 日志）与 `%APPDATA%\jinghe-desktop-shell`（Chromium 数据）。
- 静默卸载（`/S`，CI / 自动化）：`IfSilent` 直接跳过询问，一律保留数据，杜绝无人值守误删。

**导出数据备份**（关于页 → 日志与数据 → 「导出数据」，v1.1.9）：
- 把 `settings.json` + `kb/`（知识库）+ 可选 `app.log` 打包为 `.zip`，纯标准库 `zipfile`、`ZIP_DEFLATED`、原子写入（`.tmp` → `replace`）。
- 只读不改原始数据；另存为对话框默认文件名 `精核数据备份-YYYYMMDD-HHMMSS.zip`。
- 覆盖「卸载前先导出备份 → 卸载时按需删除」的完整数据主权路径。
- 单元测试：临时目录真实打包并校验 zip 内含 `settings.json` / `kb/kb.sqlite3` / `kb/note.md` / `app.log` / `备份说明.txt`；`include_logs=False` 时确认不含日志。

## 六、仍按设计保留的行为

静默卸载（`/S`）后 `%APPDATA%\jinghe-desktop-shell` 仍保留——这是 Electron 通行设计，且 v1.1.9 明确规定静默卸载不删数据（防误删）。交互卸载时用户可在弹窗中选「是」主动清除。数据可在卸载前用「导出数据」先行备份。
