## 四、后台进程实测与修复

首次实测（v1.1.5）：

- 启动后进程：`Jinghe.exe` × 4（Electron 主/渲染/GPU/工具进程）+ `resources\backend\Jinghe.exe` × 2（PyInstaller bootloader 父 + Python 子）
- 关窗后：外壳进程立即退出，**后端进程仍占端口 54324 约 20–30 秒**
- 根因：Electron 先 `backend.kill()` 杀掉 bootloader 父进程，2 秒后才 `taskkill /T`；此时父进程已死，真正的 Python 子进程已脱离进程树

修复（v1.1.6 / v1.1.7）：

1. Windows 下**先**对活着的 bootloader 执行 `taskkill /T /F`，再等待退出事件；
2. 退出后增加 `killStrayBackendProcesses()`：按 `ExecutablePath` 完整路径精确匹配 `resources/backend/Jinghe.exe`，只清 backend 目录，绝不误杀外壳；
3. 端口上已有精核后端时记录 PID（`adoptedBackendPid`），关窗一并回收，防止上次崩溃遗留的后端长期占端口；
4. 补 `backend.on('error')`，spawn 失败不再变成未捕获异常；
5. `before-quit` 改为 `preventDefault()` + 异步清理完成后再真正退出；
6. Python 后端增加 `atexit` 子进程树清理与 SIGTERM/SIGINT 处理器；看门狗强制退出前也先清子进程；
7. 新增 8 项静态守护测试（Electron 进程回收 + NSIS 卸载清理）。

## 五、需要用户决策的残留项

`%APPDATA%\jinghe-desktop-shell` 在卸载后仍保留（Chromium userData：Preferences / Local State / Cache / Local Storage 等）。这是 Electron 应用的通行做法——保留用户设置与历史，便于重装后恢复。如要求「卸载零残留」，需要新增卸载时删除该目录的逻辑，但会一并删除用户设置，**需明确确认后才做**。
