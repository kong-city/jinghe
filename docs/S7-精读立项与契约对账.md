## 2. 功能边界（做什么 / 不做什么）

### 2.1 做什么
- 输入：用户已转换好的 `.md`（来自 `out/md/*.md` 或合并文档 `MERGED.md`），**只读**
- 动作 A「提取核心」：调用本机大模型做**语义级**提炼（不是抽取首段），产出核心观点 / 结构脉络
- 动作 B「补齐知识点」：对核心涉及的概念，由大模型补充背景知识 / 术语解释 / 关联概念
- 产物：一份精读文档，落 `out/derived/<doc_id>.refine.md`

### 2.2 不做什么（红线）
1. **绝不编造原文没有的事实**：核心提取必须可回溯到源 md 的块级锚点；知识补齐必须**显式标注"由模型补充"**，与"原文核心"分区呈现，不得混为一谈
2. **不写空壳**：解析不出内容 / 模型无响应 / 分段为空 → **零产物**，不写"核心：无"的占位文档
3. **不碰冻结对账盘**：只读 `out/md/`、`MERGED.md`、`INDEX.md`；**绝不写入**这些位置（保护 SPEC §3.F 双向件数对账）
4. **不自动下载模型**：whisper 模型都不预下，大模型权重更不随软件分发、不自动拉取
5. **不改任何既有端点**：`/api/summarize` / `/api/transcribe` 空心位 / 其他端点契约全部原样
6. **不外传内容**：本机大模型在本地跑；若用户选用需网络的模型须显式配置，默认不外传

## 3. 输入契约

## 4. 产物契约

### 4.1 存放位置（沿用 S0 关键裁决）
- 产物落 `out/derived/<doc_id>.refine.md`
- **绝不**写 `out/md/*.md` / `INDEX.md` / `MERGED.md`
- `derived/` 惰性创建；空输入 / 缺工具零副作用（连目录都不建）

### 4.2 文档结构（草案，三区块 + 双注释）
```
<!-- 精核 · 精读文档 -->
<!-- src: file=<源md> | doc_id=<...> | model=<工具名+版本> | ... 8 字段来源注释 -->

## 文档信息
（源文件、生成时间、模型、参数）

## 核心提炼
（语义级核心观点 / 结构脉络；每条可回溯到源 md 的块级锚点）

## 知识点补齐
（由模型补充的背景 / 术语 / 关联概念；每条显式标注"模型补充"，与核心区分离）
```

### 4.3 provenance
- 追加写入 `out/derived/provenance_refine.json`（读旧追加、不覆盖历史）
- 每条记录：源 md、doc_id、模型名+版本、生成时间、两区块各自的分段数、是否部分成功

## 5. 本机大模型适配器契约（新增工具类型）

| 项 | 约定 |
|---|---|
| 首选工具 | **ollama**（CLI 稳定、`ollama list` 可探测、本地 HTTP API），用户本机提供 |
| 探测命令 | `ollama --version`（轻量），`probe()` 返回 `{available, path, version, reason}`，走 S1 统一 ToolAdapter |
| **不进 TOOL_SPECS** | 参照 S4 的 ffprobe 裁决：大模型探测独立挂 `refine.capability()['tools']['ollama']`，**绝不并入 `media_tools.TOOL_SPECS`**（S1 契约测试锁死 3 工具 + `capabilities()` 占位清单） |
| probe 顶层字段 | `/api/tools/probe` 新增顶层增量字段 `refine`（不 Audio/Video 那样改 tools 结构） |
| 缺工具语义 | 本机未装 ollama / 无可用模型 → 端点返回 `capability: "unavailable"` + 安装提示，UI 显示「未启用」，**零产物** |
| 模型列表 | 由 `ollama list` 读取本机已就绪模型，供用户选择；软件不下载模型 |
| 超时/取消 | 长任务独立 Job（不污染阶段 1 `/api/progress`）+ watchdog + 子进程终止；大模型推理可能数十秒，超时要给明确提示 |

## 9. 风险登记（先挂账，不承诺消除）

1. **模型幻觉**：知识补齐可能生成似是而非的内容 → 靠"分区呈现 + 显式标注模型补充 + 核心可回溯锚点"缓解，但无法根除；界面须提示"知识点由模型生成，请核对"
2. **大模型质量参差**：本地小模型（如 7B）的提炼质量有限 → 诚实展示模型名，用户自行判断
3. **长任务耗时**：CPU 推理可能数分钟 → 独立 Job + 进度 + 取消，不阻塞 UI
4. **ollama 版本差异**：不同版本 CLI 输出格式不同 → 探测做宽松解析，解析不出版本也判 available（参照 whisper），但仍真跑探测命令
