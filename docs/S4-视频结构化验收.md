## 二、专项评审与采纳情况

开工前请「视频媒体管线 / 多模态内容结构化提取」专项架构评审（只读，非通用专家）做设计评审。结论与实现对照：

| 评审要点 | 落地情况 |
| --- | --- |
| 端点与 `/api/audio/*` 对称、独立 handler | 采纳：`POST /api/video/inspect\|transcribe\|cancel` + `GET /api/video/status?since=N`；`/api/media/run` 留给 S5 |
| 双向红线（视频不复用音频，音频不反向依赖视频） | 采纳：`video_transcribe.py` 不 import `audio_transcribe`，反之亦然；`test_41` 双向源码断言锁死 |
| 画面 / 字幕只能写可验证事实，绝不编造画面描述 | 采纳：真实内嵌字幕轨机械导出 + 只读流元数据；无字幕轨只写客观状态；bitmap 字幕转 srt 失败即跳过，不 OCR |
| ffprobe JSON 优先、不进 `TOOL_SPECS`、探不到回退 `ffmpeg -i` | 采纳：ffprobe 只存在于 `video_transcribe.capability()['tools']['ffprobe']`；`probe.tools` 仍恰好 3 个工具（`test_42` 断言） |
| `-map 0:a:0` / `-nostdin` / 进程树终止 / 临时目录三链 | 采纳：所有 ffmpeg 命令带 `-hide_banner -nostdin`；抽音轨显式 `-map 0:a:0`；字幕 `-map 0:s:0 -c:s srt` |
| 视频流元数据必得 + 真实内容门禁 | 采纳并加强为**双门禁**：解析不出视频流 → 零 md；既无真实分段又无真实字幕 → 零 md |
| `/api/transcribe` 空心位与既有断言 | 原样保留：`test_34` / `test_38` 双锁、`test_06` / `test_11` 冻结内核守卫零改动 |

**未采纳项（有明确理由，已写入契约 v0.6）**：评审建议 `source_comment` 的 `anchors` 声明 `block/time/frame` 三键；本阶段未实现关键帧抽取，故只声明**实际用到**的 `block/time`，**不虚报未实现的 `frame` 键**。关键帧时间点列表列为 S5/S6 可选增强，不作为本阶段验收要求。

| 契约与文档 | `CAPABILITY_CONTRACT.md` v0.6、`S4-视频结构化验收.md`、CHANGELOG、使用说明 | 10 条 S4 裁决、S5 契约订正、验收与闸门 |
| 测试 | `test_app.py` | `test_41`（模块契约）/ `test_42`（HTTP + UI + 打包） |

**调用链**（每个视频，全程只读源文件）：

1. `ffprobe -v error -show_streams -show_format -of json`（可选）或 `ffmpeg -hide_banner -nostdin -i` → 流视图（时长 / 分辨率 / 帧率 / 视频·音频·字幕流）；
2. 有音频流 → `ffmpeg -map 0:a:0 -vn -ac 1 -ar 16000 -c:a pcm_s16le <tmp>/audio.wav` → `whisper --output_format json --output_dir <tmp>` → 读 `<stem>.json`；
3. 有字幕流 → `ffmpeg -map 0:s:0 -c:s srt <tmp>/subs.srt` → `parse_srt()` 归一化 `HH:MM:SS.mmm`；
4. 渲染恰好三区块 md，`.part` 原子替换写 `out/derived/<doc_id>.md`，provenance 读旧追加。

**诚实降级语义**：缺工具 → `capability: unavailable` + 零副作用（连 `derived/` 都不建）；无音轨 / 无字幕轨 → 对应区块只写客观状态行；抽轨 / 转写 / 解析失败 → 该侧留客观原因，靠另一侧真实内容出 md；两侧皆无或视频流元数据缺失 → **零 md**。
