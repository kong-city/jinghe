# 发版前验证清单（逐条打勾）

> 确立日期：2026-11-26
> 来源：借鉴 superpowers 的 `verification-before-completion` 理念，固化精核已有的验证动作
> 定位：**执行清单**——发版前逐条勾，没拿证据不许说"完成了"
> 配套文档：规则见 [发版流程-远端打包约定.md](发版流程-远端打包约定.md)，命令见 [本地打包指南.md](本地打包指南.md)

---

## 一、为什么要有这份清单

精核踩过的坑里，有几类是"以为完成了其实没有"：

- 升了版本号，本地 exe 还是旧版（v1.7.0 就漏过一次）；
- 改了 `ui/` 前端，没重打后端 exe，打包态服务仍返回旧界面；
- 本地包打出来了，但 `latest.yml` 的 sha512 和文件对不上；
- 验证服务用子 shell 起，工具调用一结束进程被回收，curl 拿到空响应却当成"通过"。

这份清单把验证动作写成**可打勾、有判据**的条目，每条都要求看到具体证据（数字、HTTP 码、文件名），而不是凭感觉。

## 二、发版三件套（必做，缺一不可）

### ✅ 第 1 件：发版门禁

```bash
python tools/check_release.py --no-exe
```

- **判据**：输出 `发版门禁：16 项通过 / 0 项失败`。
- **覆盖**：版本唯一来源、`ui/index.html` 无硬编码版本、`app.py` 无重复版本、CHANGELOG / 使用说明 / `electron/package.json` / `package-lock.json` / `electron/README.md` / 开发线说明全部同步到当前版本、CI workflow 完整、自更新 IPC 链完整、CI 覆盖全部测试模块、关键源文件可编译。
- **没过怎么办**：先跑 `python tools/bump_version.py --dry-run` 看差在哪，再补同步，不要手动改多处版本号。

### ✅ 第 2 件：全量单元测试

```bash
python -m unittest discover -p "test_*.py"
```

- **判据**：`Ran 435 tests ... OK`（当前基数 435 项，24 个测试模块；只增不减）。
- **注意**：项目用 **unittest**，没装 pytest。CI 里是显式列出 24 个模块跑的，本地 `discover` 等价。
- **偶发失败要警惕**：实测首次全量曾 3 项失败、耗时 495 秒（正常 143 秒），清理残留进程后二次跑 435/435 全过。根因是测试环境尾巴（刚停的 Electron/后端服务、临时目录未释放）导致个别用例超时，**不是代码缺陷**。
- **没过怎么办**：先确认无残留进程（`tasklist | grep -E "Jinghe|electron"`）和端口占用，再重跑一次；若仍失败再查代码。新增测试时不要在断言里依赖本地残留文件——CI 是 fresh checkout，曾因此出现"本地过、CI 挂"。

### ✅ 第 3 件：打包态整机探活

```bash
# 起真实后端 exe（必须用后台托管方式，不能用 (... &) 子 shell）
cd electron/<输出目录>/win-unpacked
./resources/backend/Jinghe.exe --port <临时端口> --no-browser
```

```bash
# 另开终端验证
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:<临时端口>/   # 期望 200
curl -s http://127.0.0.1:<临时端口>/api/state | head -c 120            # 期望返回当前版本号
```

- **判据**：首页返回 `200`，`/api/state` 返回的版本号 == 真源版本。
- **前端改动还要查特性是否冻进 exe**（改过 `ui/` 必做）：

```bash
curl -s http://127.0.0.1:<端口>/ui/app.js | grep -c "对应新特性的标识"
curl -s http://127.0.0.1:<端口>/ui/app.css | grep -c "对应新样式"
```

- **没过怎么办**：`ui/` 是被 PyInstaller 冻结进后端 exe 的——前端改了必须重打后端 exe 并拷进 `electron/backend/`，再重打 setup。
- **验完**：停掉后台服务（TaskStop 或对应进程管理），别留残留。

## 三、发版前·版本与产物一致性（4 条）

- [ ] **版本号只从真源改**：`extract.py::__version__` 是唯一真源，其余 7 个点用 `python tools/bump_version.py patch --reason "..."` 自动同步，**不要手工逐个改**。
- [ ] **本地包跟版本号**：升号后必须重打后端 exe + setup.exe，否则本地仍是旧版号产物。
- [ ] **前端改动必重打 exe**：只要动过 `ui/*`，就必须重打后端 exe（前端冻结在里面），否则打包态是旧界面。
- [ ] **`--require-exe` 校验产物**：本地最终确认用 `python tools/check_release.py --require-exe`，确认 `dist/Jinghe-<当前版本>.exe` 存在且版本匹配。

## 四、正式发版（push tag 触发 CI，4 条）

- [ ] **只交付 `setup.exe`**：免安装目录（`win-unpacked`）不再产出、不再交付，仅作验证中间物。
- [ ] **本地包不上传 GitHub**：正式 Release 一律 CI 远端打包；上传走 `python tools/release.py --reason "..."`，可用 `--dry-run` 预演。
- [ ] **tag 指向含当次改动的提交**：先 commit/push main，再打 tag；顺序反了 CI 构建到旧代码。
- [ ] **CI 两个 job 都绿**：test + release 均 success；检查 Release 三资产齐全（`Jinghe-<版本>-setup.exe` / `Jinghe-<版本>.exe` / `latest.yml`），`latest.yml` 的 `version` 与 tag 一致。

## 五、常见坑速查

| 现象 | 根因 | 解法 |
|---|---|---|
| Electron 启动报 `app is undefined` | 环境预置 `ELECTRON_RUN_AS_NODE=1`（WorkBuddy 自身是 Electron 应用） | `unset ELECTRON_RUN_AS_NODE && npx electron .` |
| 双击没反应、无任何错误 | 同上，进程以纯 Node 模式活着，main.js 不执行 | `Jinghe.exe --version` 若返回 v20.x 即为 Node 模式 |
| curl 拿到空响应 | 用 `(... &)` 起的子 shell 服务被工具调用结束时回收 | 用后台托管方式起服务（`run_in_background: true`） |
| 打包报 `ffmpeg.dll: Access is denied` | 残留进程占用 `win-unpacked` | 先结束 Electron / 后端进程再打包 |
| 装完启动不了（找不到后端） | 漏拷后端 exe 进 `electron/backend/` | `cp -f dist/Jinghe-<版本>.exe electron/backend/Jinghe.exe` |
| 门禁报"CI 覆盖测试模块"失败 | 新增测试模块没进 `ci.yml` 的显式列表 | 同步更新 CI 的 `python -m unittest` 模块清单 |
| 删除旧包目录失败 | 安全钩子回收站工具对 `app.asar` 报操作中止 | 需用户自己在终端 `rm -rf`，Agent 不绕过安全钩子 |

## 六、dev / prod 差异

| 维度 | dev（本地验证） | prod（CI 正式发版） |
|---|---|---|
| 打包命令 | `python build.py` + electron-builder 本地输出目录 | CI 从 tag 源码完整构建 |
| 后端 exe | 手动拷进 `electron/backend/` | CI workflow 自动建目录并复制 |
| 上传 | **禁止**上传 GitHub | `gh release create` 上传三资产 |
| 图标 | 开发态跑通用 electron.exe 需显式 `icon` 参数 | electron-builder 用 `build/icon.png` 生成 |
| 验证重点 | 界面新特性、图标、托盘是否生效 | 三资产齐全、`latest.yml` 与 sha512 匹配 |

## 七、维护

- 每次新增测试模块，同步更新第三节的测试基数与本清单"常见坑"表。
- 门禁项增减时，更新第 1 件的"覆盖"描述。
- 新踩的"以为完成了其实没有"的坑，补进第五节——这份清单靠实例生长，不写空话。
