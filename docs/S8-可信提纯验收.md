## 一、用户诉求与本轮定位

用户 2026-11-17 明确提出：

> **「对内容核心提取，不能造假」**

并就"不通过大模型能否实现知识核心提纯"讨论后拍板：

> **「补写保留，增加补写开关」**

因此 S8 不是"要不要大模型"的技术选型，而是**把可信度分层写进产品契约**：

| 档 | 能力 | 可信度依据 | 默认 |
|---|---|---|---|
| **A 可信提纯** | 抽取式核心提取（原文原句 + 关键词 + 锚点 + 打分） | **架构级保证不造假**：每句可逐字定位 | ✅ 开启 |
| **B 原文内改写** | 术语归一 / 合并去重 / 结构重排 / 排版归一（可选） | 只用原文素材，未改事实 | ✅ 开启 |
| **C AI 补写** | 补上原文没有的内容 | **按定义即生成物**，无法保证不造假 | ❌ **开关默认关闭** |

**核心裁决**：C 档保留但默认关闭；用户显式开启即视为知情同意；开启后 C 档内容**物理隔离**在独立分区、强制标注、且**不声明块锚点**。

## 二、为什么抽取式是"降风险"而非"降级"

S7 的 LLM 提纯靠**校验兜底**防编造（无效锚点观点丢弃）。抽取式是**结构上不可能编造**：

- 输出句子是原文的**原样子串**（只裁剪首尾空白、归一换行），块级锚点必然有效；
- `verify_traceable` 把这条保证变成**机器可验证**的断言，篡改即失败；
- 附带 LLM 给不出的东西：**打分与依据**（中心度 / 标题共现 / 含数据），让用户知道"这条为什么是核心"。

同时抽取式**零依赖、零下载、离线可用**：客户装 exe 即用，不必装 ollama、不下模型、不填 key。

## 四、关键实现裁决

| 裁决 / 红线 | 落地情况 |
|---|---|
| 抽取式纯标准库 | `extract_engine.py` 用 AST 扫描在测试里锁死无第三方（`test_52`） |
| 中文分词不依赖第三方 | 字符二元组 + 领域词表 + 标题挖词；**跨度冲突消解**消灭「核项」类边界碎片 |
| 结构加成不得凌驾内容重要性 | 结构先验用**倍率**而非加法：中心度是内容重要性，结构只放大、不凭空创造 |
| 纯章节标签不进候选 | 短标题（≤6 字无数字）若有下位正文承载则剔除，否则保留（避免丢信息） |
| B 档只动结构与措辞 | 白名单四项；合并用 ` ｜ ` 连接**原文**不重写；块锚点并列 |
| 排版归一**默认不做** | 它改标点会破坏「逐字定位」这条 A 档红线 → 降级为可选偏好 |
| 补写开关**真正生效** | `parse_changes(allow_suppplement=False)` 直接丢弃 add 类变更并计入 skipped —— 不是"提示核对"，是真的没有 |
| 补写物理隔离 | md 独立「AI 补充（模型生成，请核对）」分区 + `[AI ++ … ++]` 专用标记 + html `ai-item` 样式 + 头部「本文件含模型生成内容」告知 |
| 补写不声明锚点 | 它不对应任何原文块 —— 这是与原文核心最直观的区分 |
| `extract` 不进 `TOOL_SPECS` | 它是内置引擎不是外部工具；`probe.tools` 恒 3 工具（`test_33` 锁死） |
| 既有端点零改写 | `/api/summarize` `/api/transcribe` `/api/open` `/api/settings` 原样 |

## 六、风险登记（保留，不承诺消除）

1. **抽取式的深度上限**：只抽取不综合，无法跨句归纳、比较、推导；长文里选出的核心深度不如 LLM。
2. **B 档术语归一依赖共现证据**：无证据的相似写法不会被归一（宁少勿多），可能出现"本该归一却没归"的情况。
3. **C 档无法保证不造假**：只能做到"默认关闭 + 显式开启 + 物理隔离 + 强制标注 + 用户核对"。
4. **真模型质量未验**：LLM 路径全部 mock 验证工程逻辑；真实输出质量、HTTP 兼容性需客户环境验证。
5. **抽取引擎的领域词表有限**：不在词表内的领域术语只能靠二元组兜底，可能出现边界碎片（已用跨度消解压到最低）。
