## 一、本阶段目标

把**音频**文件转写成带时间戳的 Markdown，靠用户**本机**的 whisper CLI + ffmpeg 完成，软件本体仍是零第三方依赖的单文件 exe。

五条硬约束：

1. **零第三方依赖 / 工具可插拔**：模型、whisper、ffmpeg 全由用户本机提供，软件不下载、不打包、不自动安装、不内置凭据。
2. **绝不产出伪转写**：没有带时间戳且正文非空的分段就诚实失败；不生成「无语音」说明文档，不拿文件名 / 元数据 / 占位文本冒充正文。
3. **红线 2**：视频文件一律拒收，交给 S4 独立 video handler，绝不复用音频路径。
4. **冻结内核零改动**：`SPEC.md` 与 `extract.py` 主流水线一字未改，`test_06` / `test_11` 原样保留；`/api/transcribe` 的 S1 空心位原样保留。
5. **产物隔离**：只落 `out/derived/` + `provenance_media.json`（追加），绝不写 `out/md/*.md` / `INDEX.md` / `MERGED.md` / `provenance.json`。

### 调用形状

```
whisper <input> --model base --task transcribe --output_format json \
        --output_dir <temp> --verbose False
ffmpeg -hide_banner -i <input>          # 只读探测容器时长，不写文件
```

只认 `--output_format json` 的**文件输出**（`<stem>.json`），不读 stdout —— 冻结态 `sys.stdout` 可能为 None，且 stdout 用 `errors="replace"` 可能把中文静默吞成乱码却 `exit=0`，是最隐蔽的伪转写来源。srt / vtt 的逗号毫秒、BOM 与换行二次解析一并否决。

## 三、产物契约

`out/derived/<doc_id>.md`，`doc_id = doc_ + sha256(原始音频字节)[:12]`：

```
<!-- source: voice.mp3 | format: .mp3 | extracted: YYYY-MM-DD HH:MM:SS -->
<!-- src: doc_<12hex> | path: voice.mp3 | format: .mp3 | converter: whisper 1.2.3 + ffmpeg 7.0.2 | extracted: … | size: … | sha256: <64hex> | anchors: block, time -->
# voice · 音频转写

## 文档信息
- 源文件 / 格式 / 大小 / 容器时长 / 音频流 / 识别语言 / 分段数 / 生成时间

## 音轨转写
<!-- anchor: doc_<12hex> | block: 1 | time: 00:00:00.000-00:00:08.240 -->
[00:00:00.000 → 00:00:08.240] 这是第一段中文转写

## 转写元数据
- 转换器 / 适配器 / 模型 / 工具版本 / 时长探测结果 / 丢弃的非法分段 / 耗时 / sha256 / doc_id / 产物区
```

- 8 字段 `src` 固定顺序全必含，`sha256` 是完整 64 位小写 hex；`converter` **只写真实工具名 + 探测到的版本**（探不到写「版本未探测到」），绝不写「内置 ASR」造成打包引擎误导。
- 块级锚点带新增 `time` 键，`page/slide/sheet/chapter` 一律省略不留空。
- 音频**不写**「画面 / 字幕」区块 —— 那是 S4 视频三区块的专属要求。
- `provenance_media.json` 读旧追加，条目带 `capability:"audio_transcribe"`、`tool`、`model`、`segments`、`elapsed`；失败项也留痕。
- **能力级缺工具时零副作用**：连 `derived/` 都不创建，只在 `results` 与运行日志回显。

## 四、关键架构裁决

**1. 保留 `/api/transcribe` 空心位，另开 `/api/audio/*`。**
`test_34` 锁死「识别到文件也只诚实拒绝」，`test_38` 锁死「阶段 3 音视频转写需专用转写器」文案与 `el.btnTranscribe.disabled = !on || !mediaOn`。就地填充必然删改文案、既有 66 个断言立刻变红。契约 §7 也明写「不得改动既有端点旧契约」。因此 S3 走增量新端点，S4 视频再开独立 handler，`/api/media/run` 留给批量编排。

**2. 真实能力状态仍走 `/api/tools/probe` 顶层增量字段。**
`audio_transcribe.enabled` = 本机 `whisper` 与 `ffmpeg` 同时可用。`media_tools.capabilities()` 是被 `test_33` 锁死的 S1 占位清单，恒 `enabled=False`；`media_ready()` 因占位清单锁死恒 False，**不得**当 S3 就绪判据。`TOOL_SPECS` / `payload.tools` 结构零改动。

**3. 视频判定优先级高于存在性与工具检查。**
只认 `format_registry.MEDIA_AUDIO`；`media_kind(ext) == "video"` 在 `is_file()` 之前判定，且缺工具时视频仍逐条回「不支持」而非被笼统的「未启用」盖掉。**绝不沿用** `app.py:_STAGE3_AUDIO_EXT` —— 它是 `MEDIA_EXT` 并集，含全部视频后缀，是本轮识别出的最危险真实隐患。

**4. 长任务复用 S1 框架，但事件队列独立。**
`_AUDIO_JOB` 单独持有（不污染阶段 1 `/api/progress` 与件数对账），仍复用 `Job` 的 `add` / `register_child` / `cancelled` / `timed_out` 与 `start_job_watchdog`。whisper 会再派生 ffmpeg，单杀外壳会留孤儿，故新增 `media_tools.terminate_process_tree()`：Windows `taskkill /T /F /PID`，POSIX `killpg`。临时目录 `jinghe-run-audio-<pid>-<seq>` 走「父进程持有 → `finally` 删除 → `atexit` 兜底 → 启动清扫 24h 前孤儿」三链，前缀刻意与阶段 1 隔离。

**5. UI 增量不碰旧按钮。**
新增「音频转写 → .md」与「取消转写」；老的「音视频转写」占位按钮与 S1 诚实降级判定原样保留。缺工具时新按钮恒禁用并显示「未启用」。
