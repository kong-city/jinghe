# S13 · 托盘后台运行 + 应用内订阅调度（设计）

> 设计日期：2026-11-22
> 基线：jinghe v1.2.2（本地/远端同步）
> 触发：用户对 S12 裁决的第 1 点——「修改关窗就退，改为右下角图标显示，后台运行」

---

## 落地状态（2026-11-22，已完成）

- **Electron 托盘**：`main.js` 引入 `Tray/Menu/nativeImage`，内嵌经 Electron 31 实测有效的 16×16 PNG（`isEmpty()==false`）；`close` 拦截改 `hide()` 并首次气泡提示；托盘菜单「显示主窗口 / 退出精核」；`second-instance` 从托盘唤回；真正退出仍走 `shutdown()`→`stopBackendProcesses()`；`window-all-closed` 仅在无托盘降级时退出；`will-quit` 销毁托盘。
- **应用内调度**：`subscription_scheduler.py` daemon 线程 + Event 停止，启动时延迟补跑 due 项；不抢订阅引擎的单实例锁；`app.py` 启停钩子接入，`atexit` 与手动清理路径都 stop。新增 `/api/sub/scheduler` 状态端点与 UI 提示。
- **发现的真实缺陷（自检抓到）**：① 手写 base64 PNG 在 Electron 中解码成空图（托盘图标不可见）——改用标准库生成并经真实 Electron 进程验证的 PNG；② 调度线程 `Thread(args=...)` 与 `_loop` 的 keyword-only 参数不匹配导致线程启动即 TypeError——改为全 kwargs 传参（与 S12 踩过的同类坑）。
- **验收**：229 项全量测试 OK；门禁 16/16；Electron 真实进程验证托盘创建与图标有效；HTTP 端到端验证调度器常驻与订阅 API。
- **诚实边界**：托盘失效时降级为关窗即退；真正退出（托盘菜单/系统关机）仍清空进程树，不违背「退出零残留」，只是触发点从关窗移到托盘退出。

---

## 一、需求与性质变更

用户四项裁决：
1. **关窗改为托盘后台运行**（本次核心，架构级变更）；
2. 方案 B（应用内调度）作为一期基线；
3. 接受「下次启动补跑」；
4. 提纯默认抽取式，LLM 可插拔增强。

**性质**：第 1 点推翻了 jinghe 自 v1.1.5 起投入多个版本守住的「关窗即退 / 零残留」契约。这是**用户明确的新裁决**，优先级高于旧契约；但不能因此破坏「真正退出时进程树清理干净」——旧的进程回收能力必须保留，只是触发点从「关窗」移到「托盘退出」。

## 二、关键设计决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 关窗行为 | `close` 事件 `preventDefault()` + `hide()`，首次气泡提示「已最小化到右下角托盘，订阅仍在后台同步」 | 用户要的不是退出，是隐藏；后端进程与调度线程继续跑 |
| 托盘图标 | Electron `Tray` + 内嵌 `nativeImage`（data URL 的 PNG），不新增二进制资源 | 零文件依赖、打包不漏、测试友好；Windows 托盘支持 PNG |
| 真正退出 | 仅托盘菜单「退出」或 `before-quit`（系统关机/Cmd+Q）触发 `shutdown()` | 复用现有 `stopBackendProcesses()` + `cleanupDone`，自更新安装前杀后端的契约不变 |
| `window-all-closed` | **不再**调用 `shutdown()` | 关窗走 hide，此事件在隐藏模式下不会自然触发；若触发（异常路径）也不应误退后台 |
| 单实例唤起 | `second-instance` 中窗口隐藏则 `show()` + `restore()` + `focus()` | 重复双击从托盘唤回，符合桌面软件惯例 |
| 后端意外退出 | 仍 `shutdown()`，托盘在时发 `showBalloon` 提示 | 后台无 UI 时用户也需知道服务挂了 |
| 调度器 | Python 侧 `subscription_scheduler.py`，daemon 线程，随后端进程存活 | 后端常驻即调度常驻；关窗不影响。进程真退出时随后端退出，下次启动补跑 due |

## 三、必须保留的旧契约（守护测试会查）

- `stopBackendProcesses()`、`terminateProcessTree(backendPid)`、`killStrayBackendProcesses()`、`adoptedBackendPid` 回收逻辑**原样保留**；
- `app.on('before-quit')` + `event.preventDefault()` + `cleanupDone` 守卫**原样保留**；
- 自更新 `update:install` 的「先 `await stopBackendProcesses()` 再 `quitAndInstall`」时序**原样保留**；
- `autoUpdater.autoInstallOnAppQuit = false` 保留（避免后台偷偷安装）。

## 四、数据流（订阅后台运行）

```
启动：Electron 起后端 → 后端启动时 subscription_scheduler.start()（daemon 线程）
       → 立即补跑 due 订阅（下次启动补跑，兑现裁决③）
运行中：调度线程按各订阅 interval 轮询 → subscription_engine.run_due → 两层去重入库
关窗：窗口 hide 到托盘 → 后端与调度线程继续跑（用户裁决①）
退出：托盘「退出」→ shutdown() → stopBackendProcesses() → 后端 atexit 停调度线程 → app.quit
```

## 五、风险与缓解

| 风险 | 缓解 |
|---|---|
| `close` preventDefault 导致关不掉（托盘失效时用户被困） | 托盘创建失败时降级为原「关窗即退」；提供托盘菜单退出；before-quit 始终可达 |
| 后台常驻违背旧「零残留」测试 | 旧测试只查符号存在（见 test_v10_features），不查关窗即退；保留符号即可；新增托盘契约测试 |
| 调度线程与手动任务抢资源 | 复用订阅引擎单实例锁；默认间隔 24h；串行队列 |
| 自更新安装时后端被占用 | 安装前仍先 `stopBackendProcesses()`，时序不变 |
| 托盘图标在无桌面环境显示异常 | Windows 为本次目标平台；Linux/macOS 使用同一 Tray API，失败仅影响图标不影响功能 |

## 六、验收口径

- 全量测试 + 门禁全绿（含新增托盘与调度测试）；
- 静态契约：main.js 含 `new Tray`、`close` + `hide`、`shutdown` 仅在托盘退出/before-quit 触发；
- 端到端：起服务跑订阅调度（mock 依赖），验证启动时补跑 + 定时触发 + 关窗后后端仍在；
- 发版：patch 升号、commit、push、tag，CI 触发。
